# 架构说明

## 数据流

- `content.js` 从 ChatGPT 页面侧栏读取可见聊天和项目关系；监听页面变化与侧栏滚动，逐步补充已加载的聊天。它不遍历账号完整历史。
- `popup.js` 负责搜索、分页、项目树、保护规则、待删除清单、确认流程和 CSV 导出。持久设置写入 `chrome.storage.local`；扫描快照和本次选择只在当前弹窗会话中维护。
- `screenshot.js` 调用扩展内置 OCR 识别截图标题，再与当前扫描到的聊天匹配。识别本地执行，匹配结果由用户核对。

## 保护判定

手动白名单、关键词规则和项目保护任一命中即保留。项目保护默认开启，可展开项目后对单条聊天调整。手动白名单优先级最高，删除流程不能覆盖它。

## 删除流程

1. 用户在待删除清单中核对目标，并明确勾选确认。
2. 每条删除前，内容脚本校验本次扫描令牌、聊天 ID、标题、项目关系和保护规则。
3. 优先通过当前 ChatGPT 页面会话调用站点的同源会话与对话接口；只接受明确成功响应。接口不可用时尝试页面原生菜单操作。
4. 无法唯一定位、校验不一致、请求失败或遇到限流时跳过或停止，并报告结果；成功项从本次扫描快照移除，便于继续执行后续删除。

会话令牌只在内容脚本内存中临时使用，不写入扩展存储，不发送到第三方。删除不可恢复；站点接口和页面结构变化可能影响该流程。

## 权限

扩展仅申请 `storage`、`activeTab`、`scripting`，并仅匹配 `chatgpt.com` 与旧域名 `chat.openai.com`。OCR 资源随扩展打包，不依赖远程服务。
